# Rules for AI

Setup, scripts, CI and deployment: see @README.md.

## Key conventions

- **Tailwind class merging**: use the `cn()` helper from `@/lib/utils` (clsx + tailwind-merge) for conditional/merged class names. Do not concatenate class strings manually.
- **shadcn/ui**: components live in `src/components/ui/`, "new-york" style variant. Install new ones with `npx shadcn@latest add [name]`.
- **API routes**: use uppercase `GET`, `POST` exports; validate input with zod imported from `astro/zod` (zod is not a direct dependency). The existing auth routes predate this rule and cast `formData` values without validation.
- **Supabase migrations**: `supabase/migrations/` using naming format `YYYYMMDDHHmmss_short_description.sql`. Always enable RLS on new tables with granular per-operation, per-role policies. Production migrations are pushed by hand (`npx supabase db push`, see README). For `20261116120000_withdrawn_medicine_in_kit.sql` the order is merge first (Cloudflare deploys the code, which also works on the old database), then `db push`; rollback restores the previous definitions of `registry_refresh_search_list` and `registry_variant_packages` (the latter via drop + create plus its revoke/grant), then `select public.registry_refresh_search_list()`. Same order for `20261117120000_variant_key_btrim.sql` and `20261117120100_variant_key_btrim_medicine_check.sql` (the variant key trims spaces): merge, then `db push`; rollback restores `registry_refresh_search_list` and `registry_variant_packages` from `20261116120000_withdrawn_medicine_in_kit.sql` and `medicine_check` from `20261010120000_medicine_check.sql`, then `select public.registry_refresh_search_list()`. Same order for `20261118120000_medicine_check_match_level.sql` (match level `p_level` of `medicine_check`; the service sends it only for a level other than `exact`, so the merged code works on the old database at the default level, while the `all` and `any` levels get a 500 until `db push`, so push right after the merge): rollback is `drop function public.medicine_check(bigint, text)`, then restore `medicine_check(bigint)` from `20261117120100_variant_key_btrim_medicine_check.sql` with `revoke execute ... from public, anon` and `grant execute ... to authenticated`, and `medicine_check_is_generic` from `20261010120000_medicine_check.sql`.
- **Password rule rollout** (S-18, no migration): merge first (Cloudflare deploys the code), then set the production Supabase project by hand (Authentication → Policies/Providers: minimum password length 12, password requirements empty; check `secure_password_change`). Until then the app enforces the rule alone; existing accounts with a weak password are forced to change it at the next sign-in. The E2E account (`E2E_PASSWORD`) and the author's test accounts must meet the rule (see README).
- **React**: no Next.js directives ("use client" etc.). Extract hooks to `src/components/hooks/`.
- **Services/helpers** go in `src/lib/` (or `src/lib/services/` for extracted business logic).
- **Shared types** (entities, DTOs) go in `src/types.ts`.
- **Protected `main`**: the ruleset in `.github/rulesets/main.json` requires a PR (merge commits only) with the `ci` and `smoke` checks green, with no bypass. Never push to `main` directly or work around a rejected merge; renaming a CI job requires updating the ruleset. Skills that commit on the current branch (e.g. `/10x-archive`, which never branches or pushes itself) must not commit on `main`: switch to `chore/archive-<change-id>` (or another `<type>/<name>` branch) first, then ship the commit with `/ship`. `/ship` turns on GitHub auto-merge and does not wait for CI: an open PR with a red check is a signal to fix, never to bypass.

## UI

- **Tokens**: the design tokens are the `:root` values in `src/styles/global.css` (theme: light clinical teal; the palette is recorded in `context/archive/2026-10-07-search-view-tokens/palette.md`), including `success` / `warning` (with `-foreground`) for the medicine-check verdicts. Change a colour there, not in a view.
- **Role classes only**: in views use `bg-background`, `bg-card`, `text-muted-foreground`, `text-destructive`, `ring-ring` and the other role classes. Never palette classes (`text-blue-100`, `bg-slate-900`), colour functions (`rgb()`, `oklch()`, hex) or `bg-cosmic`.
- **Components**: check `src/components/ui/` before writing a control; add missing ones with `npx shadcn@latest add <name>`. Style links/buttons in `.astro` files with `buttonVariants`.
- **Guards**: `npm run ui:scan` checks the cleaned views for literal values (add a view to its list when its change cleans it); `npm run ui:shots` captures the `/szukaj` states.

## Auth flow

- `src/lib/supabase.ts` — creates a Supabase SSR client using `@supabase/ssr` with cookie-based sessions. Uses `astro:env/server` for `SUPABASE_URL` and `SUPABASE_KEY` (server-only secrets declared in astro.config.mjs `env.schema`).
- Both env vars are **optional**: when unset, `createClient()` returns `null`, auth is silently disabled (`locals.user` is always `null`), and `src/lib/config-status.ts` drives a warning banner. Every caller must handle the `null` client.
- `src/middleware.ts` — runs on every request, resolves the current user, attaches to `context.locals.user`. Redirects unauthenticated users away from routes listed in `PROTECTED_ROUTES`, and signed-in users from `/auth/signin` and `/auth/signup` to `/szukaj`.
- API endpoints: `src/pages/api/auth/{signin,signup,signout}.ts`. `signup.ts` redirects by `data.session`: a session (e-mail confirmation off) goes to `/szukaj`, none to `/auth/confirm-email`.
- Auth pages: `src/pages/auth/{signin,signup,confirm-email}.astro`, built on `src/components/auth/AuthShell.astro` and the forms in `src/components/auth/` (Polish texts, role tokens, `ui/*` components; guarded by `ui:scan`). `confirm-email` has one content ("Sprawdź skrzynkę"), with no `import.meta.env.DEV` branch.
- Protected page example: `src/pages/szukaj.astro`
- **Password rule** (S-18): at least 12 characters (code points), not on a list of common passwords, not the e-mail address; no composition rules (NIST SP 800-63B-4). `src/lib/password-policy.ts` is the pure rule shared by the forms (safe in a React island, no list); `src/lib/services/password-check.ts` adds the blocklist (`password-blocklist.json`, generated; server-only, never import it from a component). The server always checks everything before calling Supabase; `minimum_password_length = 12` in `supabase/config.toml` is the second line of defence.
- **Forced change**: `signin.ts` checks the rule on the form password after a successful sign-in and sets `password_change_required` in `user_metadata` (fail closed: if the marker cannot be written, the session is signed out with `error=password_check_failed`). The middleware sends such a user to `/konto/haslo?wymagana=1`, except `/konto/haslo`, `POST /api/auth/password` and `/api/auth/signout`. `/konto/haslo` is also the voluntary change (link in `Topbar.astro`); `src/pages/api/auth/password.ts` re-verifies the current password by signing in and then sets the new one and clears the marker in one `updateUser`. The marker is advice, not a hard gate: `user_metadata` is writable by the user with the publishable key, so a signed-in user can clear it without changing the password. Accepted gap; do not describe the gate as a guarantee.
- **Session limits**: `src/lib/session-age.ts`. Idle: the session cookie lives 30 days (`SESSION_IDLE_DAYS`); `@supabase/ssr` ignores `cookieOptions.maxAge`, so `setAll` in `src/lib/supabase.ts` caps it, and each token refresh re-issues the cookie. Absolute: the middleware reads the earliest `amr` `timestamp` from the access token (decoded only after `getUser()` verified it, no second call) and signs out a session older than 90 days (`SESSION_MAX_DAYS`) with `error=session_expired`; a token without `amr` is treated as expired and logged. The check runs before the password gate.

- `npm run smoke` — dependency-free auth-flow smoke test (`scripts/smoke.mjs`) against a running server, `BASE_URL` env (default `http://localhost:4321`). Run after dependency upgrades; CI runs it against the production preview with a local Supabase. It signs in right after sign-up, so it only passes when email confirmation is off — true for local Supabase (`enable_confirmations = false` in `supabase/config.toml`), usually not for a cloud project. The search-list steps also need the registry fixtures imported (the list must be non-empty; see `npm run registry:import` below), otherwise they fail with 404.
- `npm run roadmap:sync` — mirrors `context/foundation/roadmap.md` to GitHub Issues + the "MamLek Roadmap" project (one-way; GitHub edits to synced fields get overwritten). ## Architecture

**Astro 7 SSR app** with React 19 islands, Tailwind 4, Supabase auth, and shadcn/ui components. Runs on the Cloudflare workerd runtime (deploy target: see README).

### Rendering mode

Full server-side rendering (`output: "server"` in astro.config.mjs). All pages are server-rendered by default.
