# Rules for AI

Setup, scripts, CI and deployment: see @README.md.

## Key conventions

- **Tailwind class merging**: use the `cn()` helper from `@/lib/utils` (clsx + tailwind-merge) for conditional/merged class names. Do not concatenate class strings manually.
- **shadcn/ui**: components live in `src/components/ui/`, "new-york" style variant. Install new ones with `npx shadcn@latest add [name]`.
- **API routes**: use uppercase `GET`, `POST` exports; validate input with zod imported from `astro/zod` (zod is not a direct dependency). The existing auth routes predate this rule and cast `formData` values without validation.
- **Supabase migrations**: `supabase/migrations/` using naming format `YYYYMMDDHHmmss_short_description.sql`. Always enable RLS on new tables with granular per-operation, per-role policies.
- **React**: no Next.js directives ("use client" etc.). Extract hooks to `src/components/hooks/`.
- **Services/helpers** go in `src/lib/` (or `src/lib/services/` for extracted business logic).
- **Shared types** (entities, DTOs) go in `src/types.ts`.

## UI

- **Tokens**: the design tokens are the `:root` values in `src/styles/global.css` (theme: light clinical teal; the palette is recorded in `context/archive/2026-10-07-search-view-tokens/palette.md`), including `success` / `warning` (with `-foreground`) for the medicine-check verdicts. Change a colour there, not in a view.
- **Role classes only**: in views use `bg-background`, `bg-card`, `text-muted-foreground`, `text-destructive`, `ring-ring` and the other role classes. Never palette classes (`text-blue-100`, `bg-slate-900`), colour functions (`rgb()`, `oklch()`, hex) or `bg-cosmic`.
- **Components**: check `src/components/ui/` before writing a control; add missing ones with `npx shadcn@latest add <name>`. Style links/buttons in `.astro` files with `buttonVariants`.
- **Guards**: `npm run ui:scan` checks the cleaned views for literal values (add a view to its list when its change cleans it); `npm run ui:shots` captures the `/szukaj` states.

## Auth flow

- `src/lib/supabase.ts` — creates a Supabase SSR client using `@supabase/ssr` with cookie-based sessions. Uses `astro:env/server` for `SUPABASE_URL` and `SUPABASE_KEY` (server-only secrets declared in astro.config.mjs `env.schema`).
- Both env vars are **optional**: when unset, `createClient()` returns `null`, auth is silently disabled (`locals.user` is always `null`), and `src/lib/config-status.ts` drives a warning banner. Every caller must handle the `null` client.
- `src/middleware.ts` — runs on every request, resolves the current user, attaches to `context.locals.user`. Redirects unauthenticated users away from routes listed in `PROTECTED_ROUTES`.
- API endpoints: `src/pages/api/auth/{signin,signup,signout}.ts`
- Auth pages: `src/pages/auth/{signin,signup,confirm-email}.astro`
- Protected page example: `src/pages/szukaj.astro`

## Command tripwires

- `npx astro check` — type-check `.astro`/`.ts` files (not in `package.json` scripts; CI runs it after `npx astro sync`)
- `npm run smoke` — dependency-free auth-flow smoke test (`scripts/smoke.mjs`) against a running server, `BASE_URL` env (default `http://localhost:4321`). Run after dependency upgrades; CI runs it against the production preview with a local Supabase. It signs in right after sign-up, so it only passes when email confirmation is off — true for local Supabase (`enable_confirmations = false` in `supabase/config.toml`), usually not for a cloud project. The search-list steps also need the registry fixtures imported (the list must be non-empty; see `npm run registry:import` below), otherwise they fail with 404.
- `npm run roadmap:sync` — mirrors `context/foundation/roadmap.md` to GitHub Issues + the "MamLek Roadmap" project (one-way; GitHub edits to synced fields get overwritten). Run it after any roadmap status/item change (e.g. after `/10x-plan`, `/10x-implement`, `/10x-archive`, `/10x-roadmap`). Needs `gh` with the `project` scope (`gh auth refresh -h github.com -s project`, from a real terminal); `npm run roadmap:sync -- --dry-run` previews.
- `npm run registry:import` — imports the RPL registry XML (`scripts/registry-import.mjs`, parser in `scripts/lib/rpl-parser.mjs`) into `DATABASE_URL` as the table owner, in one transaction; `-- --file <path>` for a local file (default: download from RPL), `-- --dry-run` parses without a database. Exit 2 = usage error, 1 = import failed (rolled back). After changing the import, parser or `registry_*` migration, reset the local DB (`npx supabase db reset`), import `scripts/fixtures/rpl-sample-v1.xml` twice and `rpl-sample-v2.xml` once, then run `node scripts/registry-import-check.mjs` — CI's `smoke` job does exactly that. Production imports run daily at 04:17 UTC, plus manual dispatch, via `.github/workflows/registry-import.yml`; a failed run sends the author GitHub's failed-workflow email, and the state date on `/szukaj` is the visible freshness signal (secret `REGISTRY_DATABASE_URL`, Supavisor session-mode pooler, no `sslmode`). Non-local hosts always get TLS verified against `supabase/prod-ca-2021.crt`; one import per database at a time (advisory lock).
- `npm test` — unit and component tests (Vitest, `vitest.config.ts`; `npm run test:watch` to watch): pure logic such as `src/lib/medicine-check-verdict.test.ts` (`.test.ts`, node) and the search matching rule in `src/lib/registry-search.test.ts`, and components such as `src/components/registry/MedicineCheckResult.test.tsx` (`.test.tsx`, jsdom with Testing Library, only `fetch` replaced) and the stale-verdict scenarios of the whole screen in `src/components/registry/RegistrySearch.test.tsx` (only `fetch` and `Worker` replaced); shared helpers and fixtures live in `tests/helpers/` and `tests/fixtures/`. No database needed; not run in CI yet (planned with test-plan §3 Phase 4). It also runs the `hooks` project, `tests/hooks/agent-hooks.test.ts`: the proof of the Claude Code hooks in `.claude/hooks/` (Stop: `end-of-turn.mjs` runs ESLint + `ui:scan` on the turn's changed files and `astro check`, exit 2 sends the agent back once; PostToolUse: `format.mjs`, Prettier). Run it after changing a hook or `.claude/settings.json`. Never put test files under `src/pages/` (Astro would build them as routes); they sit next to the file they test.
- `npm run test:db` — checks the `public.medicine_check` RPC rule (`tests/db/medicine-check.test.ts`, Vitest with `vitest.db.config.ts`; same medicine by variant key incl. parallel imports and withdrawn packs, same substance by common-name set or substance set, generic placeholders never match, RLS, item order) on synthetic products, users and kit items inserted in one transaction that is always rolled back (a savepoint per test; helpers in `tests/db/medicine-check-fixtures.ts`). Every answer of the rule also goes through `parseMedicineCheck` and `checkVerdict` from `src/lib/medicine-check-verdict.ts`, the code the screen uses. `DATABASE_URL` env. Needs a local database with all migrations (`npx supabase db reset`); it does not depend on the imported registry. CI runs it in the `smoke` job right after `registry-import-check.mjs`. Run it after changing the `medicine_check` migration, `src/lib/medicine-check-verdict.ts` or the `registry_*` / `kit_items` tables. A missing or non-local `DATABASE_URL` fails the run, it never skips (local databases only).
- `npm run perf` — repeatable `/szukaj` timing (`scripts/perf-search.mjs`, Playwright + CDP throttling: Fast 4G + CPU 4x and Slow 4G + CPU 6x; list-ready time, typing `ibu 400` during loading and after) against a running server, `BASE_URL` env (default `http://localhost:4321`); `-- --profile fast|slow|both`, `-- --runs <n>` (default 5), `-- --json` (appends raw results to `.perf/perf-<date>.json`). Needs a one-time `npx playwright install chromium` (not run in CI). Locally it signs up a throwaway account (needs email confirmation off, like `smoke`); on any other host it only runs with `PERF_EMAIL`/`PERF_PASSWORD` of the user's own account — never put real credentials in commands an agent runs. Locally, serve the build with `wrangler dev`, not `astro preview`: `npx wrangler dev -c dist/server/wrangler.json --port 4321 --var SUPABASE_URL:<url> --var SUPABASE_KEY:<key>` after `npm run build`. `astro preview` drops the last chunk of a list read slowly (`ERR_CONTENT_LENGTH_MISMATCH`, so the slow profile fails with "page showed an error"). Local times differ from production (production serves the list compressed, 337 kB vs 2 MB), so compare only between runs of the same setup. Exit 2 = usage error, 1 = measurement failed.
- `npm run search:check` — compares `searchVariants` (results and order for a fixed list of ~30 queries) with a golden file in `.perf/search-golden.json` (`scripts/registry-search-check.mjs`, Node `--experimental-strip-types`), reading `registry_search_list` from `DATABASE_URL`. Needs the full registry imported locally (the fixtures are too small to be meaningful). Run `-- --save` before changing `src/lib/registry-search.ts` or how the list is built, then run it without flags after the change; after a re-import (new list `version`) save the golden file again. Exit 1 = results differ, 2 = no golden file, no or non-local `DATABASE_URL` (local databases only) or a different list `version`.
- `npm run ui:scan` — hardcoded-value scan (`scripts/ui-scan.mjs`, zero dependencies) of the views listed in its `GUARDED` array: literal colours (hex, `rgb(`, `hsl(`, `oklch(`), palette classes, `-[…px|rem]` arbitrary sizes and `bg-cosmic`. Prints `file:line: <line>` per hit; `node scripts/ui-scan.mjs <files...>` scans only the given files that are guarded (lint-staged uses this on staged `.astro`/`.tsx`; CI runs `npm run ui:scan` after lint). Add a view to `GUARDED` when its change cleans it; never list `src/components/ui/` or `global.css`. Exit 1 = hits, 0 = clean.
- `npm run ui:shots` — screenshots of `/szukaj` in each state of its `STATES` array (the 7-state matrix of the search plus the `check-*` verdict states) at desktop (1280) and phone (390) width (`scripts/ui-shots.mjs`, Playwright) against a running server: `BASE_URL=http://localhost:4321 npm run ui:shots -- --label <name>`, output in `.ui-shots/<label>/<state>-<width>.png`. Needs a one-time `npx playwright install chromium` (not run in CI) and the registry imported (the list must be non-empty). Locally it signs up a throwaway account (needs email confirmation off, like `smoke`); local hosts only. Page-level server states (registry not imported, list query failing) cannot be forced from the browser: check them by hand. Exit 2 = usage error, 1 = a state could not be reached.

Automated tests: `npm test` (unit + component, local), `npm run test:db` (rule tests against a local database, in the CI `smoke` job) and `npm run smoke`. Mutation testing (Stryker) was tried and does not work with Vitest 5 yet: see `context/foundation/test-plan.md` §6.6.

## Architecture

**Astro 7 SSR app** with React 19 islands, Tailwind 4, Supabase auth, and shadcn/ui components. Runs on the Cloudflare workerd runtime (deploy target: see README).

### Rendering mode

Full server-side rendering (`output: "server"` in astro.config.mjs). All pages are server-rendered by default.
